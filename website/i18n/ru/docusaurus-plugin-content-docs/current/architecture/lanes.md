# Партиции воркеров

Одна подписка читает все свои топики и партиции через один консьюмер, а `workers(n, by_key)`
раскладывает сообщения по партициям воркеров, выбирая их по ключу партиционирования.

<Diagram name="lanes" words={words} />

Поток подписки выдаёт по одному сообщению, из какого бы топика или партиции оно ни пришло. Без
`workers` один цикл вызывает обработчик для каждого сообщения по очереди, и ничего не выполняется
параллельно.

`workers(n, by_key)` запускает `n` партиций воркеров. Сообщение попадает в ту партицию воркеров,
на которую указывает хеш его ключа, а партиция воркеров выполняет свои сообщения по порядку.
Ключ - это [ключ партиционирования](../components/publishing/keys.md) сообщения, который доставка хранит в заголовке
`partition-key`, поэтому сообщения одного ключа сохраняют порядок. У сообщения без ключа нет
ключа партиции воркеров, и такие сообщения по кругу расходятся по партициям воркеров.

Партиции воркеров упорядочивают работу внутри одного процесса. Между процессами подписка
[`KeyShared`](../components/subscriptions/subscription-type.md) держит каждый ключ на одном консьюмере, поэтому несколько
экземпляров сервиса делят топик и всё равно сохраняют порядок каждого ключа.

[Перемотка](../components/positions/seek.md) через [`PulsarSeeker`](api:ruststream_pulsar::PulsarSeeker) сдвигает всю подписку:
каждый топик и каждую партицию, которые читает её консьюмер.

[Обработчик пакетов](../components/subscriptions/batches.md) получает пакеты, которые собирает рантайм в сервисе, потому что клиент выдаёт
сообщения по одному. В пакете не больше сообщений, чем задано в точке монтирования. Пакет
закрывается, когда он полон, или через 10 миллисекунд после первого сообщения - это
[`batch_wait`](api:ruststream_pulsar::PulsarSubscription::batch_wait) дескриптора.

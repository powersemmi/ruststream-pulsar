# Подписки

Подписка Pulsar - именованный курсор, который хранит брокер. Каждая подписка получает весь топик,
а её тип решает, как консьюмеры делят её между собой.

<Diagram name="subscriptions" words={words} />

Две подписки на один топик никак не влияют друг на друга. У каждой свой курсор, и каждая получает
все сообщения. Консьюмеры, которые подключаются под одним именем подписки, делят один этот курсор.
Подписка долговечна: она остаётся на брокере, когда уходит её последний консьюмер, и непрочитанные
сообщения копятся, пока консьюмер не вернётся.

[`SubscriptionType`](../../components/subscriptions/subscription-type.md) задаёт, как консьюмеры одной
подписки делят её между собой:

| Тип | Консьюмеры | Порядок |
|---|---|---|
| `Exclusive` | один; второй ждёт | сохраняется |
| `Shared` (по умолчанию) | все, каждое сообщение одному из них | не сохраняется |
| `Failover` | один активный, остальные в резерве | сохраняется |
| `KeyShared` | все, каждый ключ одному из них | сохраняется для каждого ключа |

Второму консьюмеру подписки `Exclusive` сервер отвечает «consumer busy». Клиент считает этот ответ
поводом повторить попытку и по умолчанию повторяет её без ограничения, раз в пять секунд. Поэтому
второй консьюмер ждёт, пока уйдёт первый, и его сервис не запускается.
[`OperationRetries`](../../components/broker/operation-retries.md) ограничивает число попыток, и тогда
подписка возвращает ошибку
[`PulsarError::Subscribe`](api:ruststream_pulsar::PulsarError::Subscribe).

Сервер создаёт подписку, когда консьюмер впервые её называет, и ставит её на самое новое
сообщение: клиент `pulsar` запрашивает эту позицию, если не указано иное, и этот крейт её не
меняет. Сервис, которому нужно начать с другого места, переставляет подписку
[перемоткой](../../components/positions/seek.md), позицию которой задаёт
[`PulsarPosition`](../../components/positions/index.md). Перемотка сдвигает сам
хранимый курсор, поэтому действует при каждом старте, а не только при первом.

Подписка на [список топиков](../../components/subscriptions/topics.md) или на
[шаблон](../../components/subscriptions/pattern.md) - это внутри клиента по консьюмеру на топик, которые
читаются как один поток. Шаблон сопоставляется с полными именами топиков. Клиент заново получает
список топиков каждые 30 секунд, поэтому топик, созданный после подписки, присоединяется к ней при
следующем обновлении списка.

Эта модель взята у самого Apache Pulsar
([подписки](https://pulsar.apache.org/docs/next/concepts-messaging/#subscriptions),
[типы подписки](https://pulsar.apache.org/docs/next/concepts-messaging/#subscription-types)).
Как консьюмер подтверждает сообщения, показывает страница [Подтверждение](acknowledgement.md).
